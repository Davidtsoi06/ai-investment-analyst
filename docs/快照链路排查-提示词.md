## 排查清单（按优先级逐项查证，给出证据）

### 1. 导出是否真的被触发（调用链完整性）
- 读 ipc/asset-ipc.ts 全文：exportPortfolioSnapshot / schedulePortfolioExport 的所有调用点（买卖、编辑、价格刷新、其它持仓变化）
- 逐一点确认调用点所在的 IPC handler 是否真的被前端调用（搜对应 invoke 名在 renderer 的调用处）
- 价格批量刷新（现价变化）的轮询/定时逻辑在哪、是否真的运行（注意 schedulePortfolioExport 30 秒节流 + 模块级 lastExportAt 的边界）
- 结论：哪些操作路径会触发？用户日常操作（如打开软件/录入一笔/刷新价格）能否触发？

### 2. 导出执行是否会静默失败（重点）
- services/ai-portfolio-service.ts 的 exportPortfolioSnapshot：catch 只 console.error（渲染进程控制台不可见）→ 任何一步异常都会静默
- 逐行检查这些高风险点：
  a) require('../../../package.json')：Electron 打包后（app.asar 内）该相对路径是否仍能解析？如果 main 入口在 src/main/xxx.ts 编译到 dist/，从 dist 内回退三级是否越出 asar 根而失败？**头号嫌疑**：一旦 require 抛 MODULE_NOT_FOUND，整个函数静默退出，文件永远不写
  b) folder 目录不存在时 fs.writeFileSync 会抛错（无 mkdir 逻辑）——确认目标目录是否由某方创建（搜两项目里对该目录的 mkdir/创建代码）
  c) getDatabase() 同步打开是否可能抛错；db.prepare 的 SQL 列名与真实表结构是否一致（如 assets 表缺某列 → 抛错静默）
  d) JSON.stringify(snapshot) 前字段取值（如 latest 可能 null）是否会导致异常

### 3. 设置链路
- 设置卡片 AiConfigCard.tsx：chooseFolder → ipc aiPortfolio:chooseFolder → setPortfolioFolder → setSetting('aiPortfolio.folder')；确认读写 key 一致、无拼写差异（FOLDER_KEY='aiPortfolio.folder'）
