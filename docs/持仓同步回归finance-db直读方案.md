# 持仓数据来源回归方案：直接读取理财软件数据库（finance.db 直读）

> 目标版本：v1.1.7 ｜ 状态：待用户确认后实施
> 背景：快照文件模式（v1.0.5 起）在部分电脑上"拿不到文件"（依赖理财软件在**同一台电脑**正确配置并持续导出）。
> 用户决策：回归 v1.0.4 及以前的做法——本软件直接只读理财软件的 finance.db，免去"导出配置/文件流转"整条链路。

---

## 一、方案目标

1. **零配置**：装好理财软件（本机）→ 本软件自动发现 finance.db → 一键同步持仓
2. **换电脑不再折腾**：路径基于 %APPDATA% 自动随用户名，任何电脑装上两个软件即通（理财软件侧无需任何导出设置）
3. **保持安全**：全程**只读**理财软件数据库，绝不写入/修改；沿用本地 holdings 表作为唯一数据出口，风险分析/复盘/问答/收盘报告零改动
4. **平滑兼容**：已生成的快照文件仍作为自动兜底；手动录入模式保留

## 二、现状与事实（已实测确认）

| 项 | 结论 |
|---|---|
| finance.db 位置 | %APPDATA%\personal-finance\finance.db（自动随用户名） |
| 加密 | 无加密（明文 SQLite；secret.key 仅加密设置项） |
| 锁定风险 | better-sqlite3 默认 DELETE 日志模式，无 -wal 文件；只读查询可与运行中的理财软件并存（busy 短暂重试即可） |
| 持仓表 | assets（code/name/market/currency/quantity/cost_price…，含券商/银行归属、账户现金 investment_accounts.cash_balance、净值历史 net_worth_history） |
| 直读历史 | v1.0.4 及以前本软件一直直读，功能成熟 |

## 三、设计

### 3.1 数据流（与现快照模式同构，只换"源"）
```
finance.db（只读）
  ├─ assets             → holdings 表（source='portfolio_app'）【数量/成本/名称/代码/市场】
  ├─ investment_accounts → 账户列表与现金余额（缓存至 system_settings）
  ├─ net_worth_history   → 近 180 天净值（缓存，仪表盘净值图/复盘用）
  └─ transactions        → 近 100 条交易（第二版再启用，本期不含）
现价/盈亏：完全走本软件行情源（v1.1.5 每 5 分钟刷新机制，与源无关）
```

### 3.2 读取优先级（"快照模式"语义升级为"自动来源"）
1. **finance.db 直读**（主）：检测 %APPDATA%\personal-finance\finance.db 存在 → 直读
2. **快照文件兜底**（兼容）：finance.db 不存在时，检查 data\portfolio\portfolio_snapshot.json（老配置的理财软件导出仍可用）
3. 两者皆无 → 明确提示原因："未检测到理财软件数据库（…finance.db），请确认本机已安装并运行过「个人理财投资软件」；或切换手动录入模式"

### 3.3 只读安全
- sqlite3 URI `mode=ro` 打开；连接超时 5s；busy 重试 3 次（理财软件正在写时短暂等待）
- **零写操作**：不建表、不写 finance.db 任何内容（读取后即关闭）
- schema 防御：读取前 PRAGMA table_info 校验必需列，理财软件未来改表不会导致本软件崩溃（缺列则跳过并提示）
- 杀软误报缓解：单一白名单式路径访问、纯读行为；README 增加说明（若杀软误报属已知开源无签名现象，见 5.2）

### 3.4 同步触发（沿用现机制）
- 手动"同步持仓"按钮、每小时自动同步（整点后 5 分钟）、模式切换后自动同步
- 同步后立即触发 v1.1.5 现价刷新（行情实时化不变）

### 3.5 界面文案调整
- 设置页「持仓数据来源」：模式说明由"快照文件"改为"理财软件数据库直读（推荐）"
- 持仓总览/同步失败提示：直接给出检测到的原因与目标路径（同"诊断可见化"）

## 四、文件级改动清单（全部在本软件仓库）

| 文件 | 改动 |

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 杀软把"读他应用数据库"当可疑 | 只读+固定路径；README 误报说明；与 v1.0.5 前的实际差异：此次不打包 onefile、行为更收敛 |
| 理财软件升级改表结构 | PRAGMA 列校验+容错跳过，缺关键列提示升级 |
| 理财软件运行中被读（busy） | mode=ro + 5s 超时重试；读失败不影响主流程并提示稍后重试 |
| 本软件与理财软件版本不配套 | 数据字段按代码/名称/数量/成本四要素最小契约，两项目长期稳定 |
| 跨电脑使用 | 直读只支持同机（重要边界）；跨机场景后续用「导入快照文件」按钮/网盘方案补充（本期不含） |

## 六、测试清单（实施后冒烟）
1. 理财软件运行中（本机已装、库有持仓）→ 一键同步 → holdings 与 finance.db 一致；现价刷新正常
2. 理财软件未安装（模拟：改名 finance.db）→ 明确提示原因；快照兜底若存在则回退成功
3. 手动模式不受影响
4. 持仓编辑（理财软件侧）→ 再次同步 → 数量/成本更新
5. 净值历史/账户现金在仪表盘正常（与快照模式输出一致）
