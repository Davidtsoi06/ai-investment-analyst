## 一、总体架构

五层架构（见需求文档 2.1）：
L5 用户交互层（React 渲染进程）→ L4 智能体编排层（8 个 Agent）→ L3 AI 模型与记忆层（DeepSeek + 用户画像/虚拟账本/历史记忆）→ L2 数据处理层（调度/清洗/融合/缓存/存储）→ L1 数据源接入层（行情/资讯/理财软件/宏观）。

## 二、技术选型（已确认）

## 三、进程模型与通信

Electron 主进程（Node）包含：系统托盘 / 开机自启 / 生命周期管理；拉起 Python 子进程（PyInstaller 单文件 exe，child_process）；渲染进程（React，IPC via preload contextBridge）经主进程代理访问 Python 后端（localhost 随机端口 + 启动令牌）。

规则：
- 渲染进程不直接访问文件系统/数据库，一律走 IPC。
- Python 后端监听 127.0.0.1 随机端口，启动时生成一次性令牌，Electron 持有并校验。
- Python 子进程崩溃：Electron 自动重启（每小时最多 N 次，防死循环）。
- 版本配套：后端 exe 与前端版本号不一致时以安装包内置为准。

## 五、数据库设计（SQLite 主库 ai_invest.db）

核心表（14 张，见需求文档 6.2）：user_profile / holdings / watchlist / tracking / tracking_events / recommendations / recommendation_performance / news_cache / daily_summary / review_reports / notification_log / macro_indicators / market_sentiment / system_settings。
约定：
- 所有表含 created_at / updated_at（UTC 存储，展示转北京时间）。
- 金额以最小单位整数或 DECIMAL 存储，禁止浮点累计；币种字段必填。
- 时间一律 ISO-8601 字符串。
- 数据库迁移：版本化迁移（migrations 表记录版本）。

## 六、行情数据模型与多源融合

统一输出模型：symbol / name / market（A股|HK|US）/ currency / price / change_pct / volume / amount / timestamp / source。
- 主源优先，主源异常自动切备用源，连续失败熔断 + 日志。
- 轮询间隔：A 股 10~30 秒、港股/美股 1~5 分钟（与数据源延迟匹配，已确认）。
- 缓存：realtime 缓存 60 秒内复用；daily K 线缓存到 cache/daily，保留最近 1 年。
- 交易日历：三市场各自节假日判断（AKShare 交易日历接口），非交易日不轮询不推送。

## 七、理财软件对接规范（只读）

- 数据源：C:/Users/用户/AppData/Roaming/personal-finance/finance.db
- 打开方式：SQLite URI 只读模式（mode=ro），严禁任何写操作；WAL 并发实测。
- 字段映射（已实地调研表结构）：
  - assets → holdings（持仓：code/name/quantity/cost_price/current_price/market_value/profit_loss）
  - investment_accounts → 投资账户总览（broker/cash_balance）
  - accounts + account_balances → 现金/银行资产
  - transactions → 历史交易
  - net_worth_history → 净值走势
  - currencies + exchange_rates → 汇率折算
- 加密风险：目录存在 secret.key，部分字段可能 AES-256-GCM 加密；P1 验证，若加密则在理财软件侧增加导出持仓 JSON 功能（自研可控）。
- 同步频率：每小时 + 手动触发；同步失败不影响其他功能。

## 八、代码规范

- TypeScript：strict 模式；组件函数式；状态用 Zustand；IPC 频道集中定义。
- Python：类型注解；模块按 agents/data_sources/services/models/utils 分层；Agent 统一接口（run(context) → result）。
- Prompt 模板集中在 backend/app/utils/prompts/，输出要求 JSON 结构化，便于解析。
- 提交信息：约定式提交（feat:/fix:/docs:/chore:/refactor:/test:）。
- 错误处理：后端统一异常响应格式；前端统一错误提示组件；关键路径写日志。

## 九、安全规范

- .env 与所有密钥绝不提交（.gitignore 强制 + 提交前检查脚本）。
- DeepSeek Key：本地 AES 加密存储，仅后端进程持有。
- 理财软件数据库只读；AI 软件自身数据库不做远程访问。
- 公开仓库中不得包含任何真实个人数据样本。

## 十、测试策略

- 单元测试：后端纯函数（指标计算/去重/映射）、前端工具函数（Vitest）。
- 集成测试：后端接口（pytest + FastAPI TestClient）；行情源 mock。
- 手动验收：每个步骤的验收标准（见开发执行计划）；版本发布前全流程回归。
